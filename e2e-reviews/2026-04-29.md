## 🔴 高優先度（修正推奨）

### [H-1] `test.beforeAll` + shared `page` 変数によるテスト間の状態共有

- **ファイル**: [tests/careecon_construction_detail.spec.ts:34-54](tests/careecon_construction_detail.spec.ts#L34-L54)
- **該当コード**:
  ```typescript
  test.describe('建設トレンド 記事詳細', () => {
    let page: Page;  // ← describe スコープで共有

    test.beforeAll(async ({ browser }) => {
      // ... ページを取得して page に代入
      page = await browser.newPage();
      await page.goto(detailUrl, { waitUntil: 'load' });
    });

    test('記事詳細ページの URL が /blog/{id} 形式である', async () => {
      await expect(page).toHaveURL(...); // ← 共有 page を使用
    });
    // 以降の5テストも同様
  ```
- **問題**: describe スコープの `page` 変数を6つのテストで共有しています。`beforeAll` が失敗すると後続6テストがすべてスキップされ、どのテストが本来失敗するかわかりません。また、テストが共有 page の状態に依存するため、将来テストを並び替えたり独立して実行したりする際に予期しない失敗が起きます。
- **推奨修正**:
  ```typescript
  // beforeEach に変えて各テストで独立したページを使う
  test.describe('建設トレンド 記事詳細', () => {
    let detailUrl: string;

    test.beforeAll(async ({ browser }) => {
      // URLだけ取得・共有する（状態を持たない文字列なので安全）
      const tempPage = await browser.newPage();
      await tempPage.goto(CATEGORY_URL, { waitUntil: 'domcontentloaded' });
      const hrefs = await tempPage.locator('a[href*="/blog/"]').evaluateAll(
        (els) => els.map((el) => el.getAttribute('href') ?? '')
      );
      const articleHref = hrefs.find((href) => /\/blog\/\d+$/.test(href));
      expect(articleHref, '記事リンクが見つかりません').toBeTruthy();
      detailUrl = articleHref!.startsWith('http')
        ? articleHref!
        : `https://careecon.jp${articleHref}`;
      await tempPage.close();
    });

    test('記事詳細ページの URL が /blog/{id} 形式である', async ({ page }) => {
      await page.goto(detailUrl);
      await expect(page).toHaveURL(/careecon\.jp\/blog\/\d+/);
    });
    // 各テストが自分で goto する形に変更
  ```

### [H-2] `throw new Error()` によるアサーションの代替

- **ファイル**: [tests/careecon_construction_detail.spec.ts:14](tests/careecon_construction_detail.spec.ts#L14), [tests/careecon_construction_detail.spec.ts:45](tests/careecon_construction_detail.spec.ts#L45)
- **該当コード**:
  ```typescript
  const articleHref = hrefs.find((href) => /\/blog\/\d+$/.test(href));
  if (!articleHref) throw new Error('記事リンクが見つかりません');
  ```
- **問題**: `throw` で終わるとPlaywrightのリトライ・トレース記録が正しく動作しません。失敗時のスクリーンショットやビデオが保存されず、テストレポートでの表示も崩れます。
- **推奨修正**:
  ```typescript
  const articleHref = hrefs.find((href) => /\/blog\/\d+$/.test(href));
  expect(articleHref, '記事リンクが見つかりません').toBeTruthy();
  ```

## 🟡 中優先度（改善推奨）

### [M-1] `evaluateAll` で href を取得してから `goto` するパターン（S-3）

- **ファイル**: [tests/careecon_construction_detail.spec.ts:10-20](tests/careecon_construction_detail.spec.ts#L10-L20), [tests/careecon_construction_detail.spec.ts:41-53](tests/careecon_construction_detail.spec.ts#L41-L53)
- **該当コード**:
  ```typescript
  const hrefs = await page.locator('a[href*="/blog/"]').evaluateAll(
    (els) => els.map((el) => el.getAttribute('href') ?? '')
  );
  const articleHref = hrefs.find((href) => /\/blog\/\d+$/.test(href));
  // ...
  await page.goto(detailUrl, { waitUntil: 'load' });
  ```
- **問題**: URLの構造（`/blog/数字`）という実装詳細に依存しています。URLパターンが変わるとテストが壊れます。また「クリックして遷移する」という実際のユーザー操作を検証していないため、クリックが壊れても検出できません。コメントに「カルーセルのJSが tabindex を書き換えるためクリックできない」とありますが、このサイト固有の制約として理由が明記されている点は良いです。
- **推奨修正（制約がある場合の対応）**: 制約理由のコメントは残しつつ、`evaluateAll` の代わりに `getAttribute` を使ってauto-waitingを活かす:
  ```typescript
  // カルーセルはJSが動的にtabindexを書き換えるため直接URLへ遷移する（サイト固有の制約）
  const firstArticleLink = page.locator('a[href*="/blog/"]').filter({
    hasText: /.+/ // リンクテキストがあるもの
  }).first();
  const href = await firstArticleLink.getAttribute('href');
  expect(href).toMatch(/\/blog\/\d+$/);
  ```

### [M-3] `locator('time').first()` のインデックス指定（F-5 + S-2）

- **ファイル**: [tests/careecon_construction_detail.spec.ts:86](tests/careecon_construction_detail.spec.ts#L86)
- **該当コード**:
  ```typescript
  const timeEl = page.locator('time').first();
  ```
- **問題**: ページに `<time>` 要素が複数ある場合（公開日・更新日など）、`.first()` は最初に出現した要素を取得します。DOMの順序が変わるとテストが別の要素を取得します。
- **推奨修正**:
  ```typescript
  // datetime 属性があるものを明示的に指定
  const timeEl = page.locator('time[datetime]').first();
  // または公開日ラベルの近くにあるものを getByText で絞り込む
  ```
