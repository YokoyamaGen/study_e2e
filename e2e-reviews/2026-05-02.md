## 🔴 高優先度（修正推奨）

### [H-1] `waitForFunction` がカルーセル（人気記事）のリンクを「新着先頭記事」として取得している

- **ファイル**: [tests/careecon_construction_detail.spec.ts:11-19](tests/careecon_construction_detail.spec.ts#L11-L19)
- **該当コード**:
  ```typescript
  const handle = await page.waitForFunction(() => {
    const links = [...document.querySelectorAll('a[href*="/blog/"]')];
    const href = links
      .map((el) => el.getAttribute('href') ?? '')
      .find((h) => /\/blog\/\d+/.test(h));
    if (!href) return null;
    return href.startsWith('http') ? href : `https://careecon.jp${href}`;
  });
  ```
- **問題（ページ構造の分析による）**: このページの DOM は以下の順序で構成されている。
  1. **スリックカルーセル**（`slick-carousel-box`、位置 ~75,800 byte）— `class` なしの `<a href="/blog/数字">` タグ。表示されているのは**人気記事**であり新着記事ではない（例: `/blog/4593551861` は 2024-10-30 付けの記事）。
  2. **新着記事一覧**（`blog-contents`、位置 ~84,700 byte）— `<a class="cover-link" href="/blog/数字">` タグ。こちらが本来の「新着」記事。

  `a[href*="/blog/"]` で取得すると**カルーセルのリンクが DOM 上で先に出現する**ため、常に人気記事へ遷移してしまう。テスト名「新着一覧の先頭記事」とは乖離しており、カルーセルの内容が変更された場合（記事の削除・差し替え）にテストが失敗するリスクがある。

- **推奨修正**:
  ```typescript
  // a.cover-link は新着記事リスト（blog-contents）専用のセレクター
  // カルーセルは class なし <a> を使うため、cover-link で絞り込むと新着先頭記事が取得できる
  const firstCoverLink = page.locator('a.cover-link').first();
  const href = await firstCoverLink.getAttribute('href');
  expect(href, '新着先頭記事のリンクが取得できません').toMatch(/\/blog\/\d+/);
  ```

### [H-2] SSR 済みコンテンツに `page.waitForFunction()` を使用（不要な複雑さ・Flaky リスク）

- **ファイル**: [tests/careecon_construction_detail.spec.ts:11-19](tests/careecon_construction_detail.spec.ts#L11-L19)
- **問題**: `waitForFunction()` はブラウザコンテキスト内で関数をポーリングする API であり、JS による**動的なコンテンツ生成後**に DOM を確認したい場合に使う。しかし実際には記事リンクはサーバーサイドレンダリング（SSR）で初期 HTML に含まれており、`domcontentloaded` 後に即座に利用可能。`waitForFunction` を使うことで以下の Flaky リスクが生じる。
  - JS ハイドレーション（React 等）が DOM を一時的に書き換える瞬間にポーリングが走ると、リンクが見つからない状態になる可能性がある。
  - ブラウザコンテキストの評価関数は Playwright の auto-waiting の恩恵を受けられない。
  - `handle.jsonValue()` の型キャストにより TypeScript の型安全性が失われる。

- **推奨修正（[H-1] の修正と組み合わせる）**:
  ```typescript
  // Playwright の locator auto-waiting を使う（waitForFunction 不要）
  const firstCoverLink = page.locator('a.cover-link').first();
  await expect(firstCoverLink).toBeVisible(); // 要素が現れるまで待機
  const href = await firstCoverLink.getAttribute('href');
  expect(href, '新着先頭記事のリンクが取得できません').toMatch(/\/blog\/\d+/);
  const detailUrl = href!.startsWith('http')
    ? href!
    : `https://careecon.jp${href!}`;
  ```

## 🟡 中優先度（改善推奨）

### [M-1] 詳細ページへの遷移に `waitUntil: 'domcontentloaded'` を使用

- **ファイル**: [tests/careecon_construction_detail.spec.ts:22](tests/careecon_construction_detail.spec.ts#L22)
- **該当コード**:
  ```typescript
  await page.goto(detailUrl, { waitUntil: 'domcontentloaded' });
  ```
- **問題**: `domcontentloaded` は HTML のパース完了時点で発火するため、JS によるハイドレーションや遅延レンダリングが完了する前にアサーションが実行される可能性がある。`expect(heading).toBeVisible()` が auto-waiting（デフォルト 5 秒）を持つため現状は救われているが、ネットワークが遅い CI 環境ではタイムアウトするリスクがある。
- **推奨修正**: 詳細ページへの goto は `'load'` に変更し、ページの主要リソース読み込み完了を待つ。
  ```typescript
  await page.goto(detailUrl, { waitUntil: 'load' });
  ```

- **ファイル**: [tests/careecon_construction_detail.spec.ts:6](tests/careecon_construction_detail.spec.ts#L6)
- **該当コード**:
  ```typescript
  test('新着一覧の先頭記事をクリックすると詳細ページが表示される', async ({ page }) => {
  ```
- **問題**: テスト名は「クリックすると」とあるが、実際にはリンクをクリックせず `page.goto()` で直接 URL に遷移している。カルーセルの tabindex 書き換えが理由とコメントに記載があるが、テスト名がユーザー操作（クリック）を示しているため、テスト内容と名前が食い違う。テスト名を読んだ人が「クリックのテストが通った」と誤解するリスクがある。
- **推奨修正**: テスト名を実際の動作に合わせる。
  ```typescript

  ```

## 修正後の完成形（参考）

```typescript
import { test, expect } from '@playwright/test';

const CATEGORY_URL = 'https://careecon.jp/blog/category/construction';

test.describe('建設トレンド 新着記事詳細遷移', () => {
  test('新着一覧の先頭記事の詳細ページが表示される', async ({ page }) => {
    await page.goto(CATEGORY_URL, { waitUntil: 'domcontentloaded' });

    // a.cover-link は新着記事リスト専用セレクター（カルーセルの a タグと区別できる）
    // カルーセルはJSが動的にtabindexを書き換えるため、クリックせず直接URLへ遷移する
    const firstCoverLink = page.locator('a.cover-link').first();
    await expect(firstCoverLink).toBeVisible();
    const href = await firstCoverLink.getAttribute('href');
    expect(href, '新着先頭記事のリンクが取得できません').toMatch(/\/blog\/\d+/);

    const detailUrl = href!.startsWith('http')
      ? href!
      : `https://careecon.jp${href!}`;

    await page.goto(detailUrl, { waitUntil: 'load' });

    await expect(page).toHaveURL(/careecon\.jp\/blog\/\d+/);

    const heading = page.getByRole('heading', { level: 1 });
    await expect(heading).toBeVisible();
    const text = await heading.textContent();
    expect(text?.trim().length).toBeGreaterThan(0);
  });
});
```

---

## 良い点

- `getByRole('heading', { level: 1 })` のような意味的セレクターを使っており、HTML リファクタリングに強い
- カルーセルの tabindex 制約コメントが残されており、`goto` による直接遷移の意図が伝わる
- `toHaveURL(/careecon\.jp\/blog\/\d+/)` でアサーションパターンが明確
- `waitUntil: 'domcontentloaded'` をカテゴリページで使う判断は適切（SSR ページのため `load` まで待つ必要がない）
